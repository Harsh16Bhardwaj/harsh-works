# Content Rules

## Main principle

Every claim should connect to proof.

## Copy style

Short, specific, active, and honest.

## Banned language

- passionate developer
- tech enthusiast
- quick learner
- aspiring engineer
- innovative solutions
- cutting-edge technologies
- love to code

## Use instead

- built
- designed
- automated
- validated
- debugged
- shipped
- documented
- mapped
- ranked
- measured

## Project card format

Each Project Gallery card should include:

1. Project name
2. System identity
3. Problem -> System -> Proof
4. Lane
5. Tech tags
6. CTA: Open Case File

## Proof honesty

Do not invent metrics.
Do not invent users.
Do not invent deployment status.
Mark missing proof explicitly.

## Live status examples

- Training JEDI ranking model again
- Reading about feature stores
- Fixing NameFrame delivery queue
- Exploring RoomSense class imbalance
- Mapping GitHub proof trail
- Turning ML notes into case studies
