# Copy Decringifier

## Mission
Remove weak, generic, cringe, or fake-sounding portfolio language.

Replace it with short, proof-backed, system-oriented copy.

## Banned phrases

Avoid these unless there is a very specific reason:

- passionate developer
- tech enthusiast
- aspiring software engineer
- motivated learner
- quick learner
- always eager to learn
- I love coding
- innovative solutions
- cutting-edge technology
- robust and scalable solution without proof
- dynamic web application
- user-friendly interface
- seamless experience
- modern design
- end-to-end solution without explaining end-to-end

## Preferred phrases

Use proof-oriented verbs:

- built
- designed
- automated
- validated
- debugged
- shipped
- mapped
- ranked
- measured
- documented
- refactored
- tested
- converted
- analyzed

Use concrete nouns:

- workflow
- queue
- fallback
- proof trail
- case file
- notebook
- model
- validation
- dashboard
- scraper
- pipeline
- map
- build log
- architecture
- interface

## Copy formula

### Hero copy

Bad:

> I am a passionate developer who loves building innovative solutions.

Good:

> I build ML products, full-stack systems, and public learning trails.

### Project copy

Bad:

> A React app made using Next.js and Tailwind.

Good:

> A certificate automation system that turns CSV event data into verified, batch-delivered certificates.

### About copy

Bad:

> I am always eager to learn new technologies and solve problems.

Good:

> I learn by turning concepts into public artifacts: notes, notebooks, dashboards, models, and deployed tools.

### Skills copy

Bad:

> Skilled in React, Python, Machine Learning, SQL, Tailwind.

Good:

> I work across three lanes: ML/data validation, full-stack product systems, and automation workflows.

## Tone rules

The copy should be:

- short
- specific
- active
- honest
- technical but understandable
- ambitious but grounded

The copy should not be:

- insecure
- corporate
- overhyped
- buzzword-heavy
- too humble
- fake confident

## Rewrite process

When invoked:

1. Identify weak lines.
2. Explain why they are weak.
3. Rewrite in Harsh's portfolio voice.
4. Keep the copy short.
5. Preserve truth; do not invent proof.

## Output format

```md
## Copy Review

### Weak / generic
<original>

### Issue
<why it weakens identity>

### Replacement
<better copy>
```

## Final filter

Before finalizing any text, ask:

- Can a thousand other students say the same thing?
- Does it prove anything?
- Is there a stronger verb?
- Is there a concrete system, artifact, or decision?
