# Portfolio Identity Director

## Mission
Make Harsh Bhardwaj's portfolio feel like a **builder command center**, not a generic student resume.

The site must communicate this within the first 15 seconds:

> I build ML products, full-stack systems, and public learning trails.

The visitor should remember:

- Harsh builds real systems, not only tutorials.
- His GitHub is a proof trail.
- His work spans ML/data, full-stack products, automation, agents, and learning systems.
- He explains decisions, tradeoffs, failures, and validation instead of only listing stacks.

## Fixed identity

Name: Harsh Bhardwaj

Primary identity:

- ML products
- Full-stack systems
- Automation workflows
- Public learning trails
- Agentic / Codex-assisted engineering workflows

Primary line:

> I build ML products, full-stack systems, and public learning trails.

Secondary lines that may be used:

- My GitHub is not a dump. It is a proof trail.
- I learn by turning concepts into public artifacts.
- I turn messy workflows into systems, notes, models, dashboards, and deployed tools.
- I care about the parts people usually skip: validation, queues, failure paths, logs, and documentation.

## What to avoid

Do not write:

- passionate developer
- tech enthusiast
- aspiring software engineer
- self-motivated learner
- quick learner
- I love coding
- exploring the world of technology
- building innovative solutions without proof
- generic student portfolio copy
- generic SaaS landing page copy

Avoid pages that feel like:

- a resume pasted into cards
- random project grid
- template portfolio
- overdone neon hacker theme
- empty cinematic drama
- toy 3D demo unrelated to the story

## Preferred language

Use verbs that prove action:

- Built
- Designed
- Automated
- Validated
- Debugged
- Shipped
- Mapped
- Tested
- Documented
- Refactored
- Ranked
- Measured
- Rebuilt
- Turned into

Use system nouns:

- pipeline
- proof trail
- workflow
- queue
- fallback
- dashboard
- validation wall
- case file
- build log
- repo cluster
- console
- lab
- shelf
- map

## First five sections identity requirement

The first five sections are fixed:

1. Hero / Current Identity
2. About Me / Builder Thesis
3. GitHub Map
4. Work Console
5. Project Gallery

Together they should answer:

1. Who is Harsh right now?
2. What does he build?
3. How does he learn?
4. Where is the proof?
5. Which projects deserve attention first?

## Hero rules

The Hero must include:

- Harsh Bhardwaj
- Primary line: "I build ML products, full-stack systems, and public learning trails."
- Current direction: AI/ML + full-stack + automation + public learning systems
- Live status chips
- Three.js sakura-petal visual scene, if implemented
- Primary CTA: View Systems / Open Case Files
- Secondary CTA: GitHub / Resume

Live chips can include:

- Training JEDI ranking model
- Building ML Lab
- Refining NameFrame queue
- Mapping GitHub proof trail
- Exploring agents + automation
- Open to SDE / ML / AI engineering roles

## About section rules

The About section should not be a biography dump.
It should be a builder thesis.

Required thesis structure:

1. How I learn
2. How I build
3. Why GitHub is proof
4. Why public artifacts matter

Suggested flow:

> I learn by building public trails. When I study a concept, I turn it into a note, notebook, dashboard, model, system, or repo. That makes GitHub my proof trail: not just code, but a record of what I tried, broke, measured, and improved.

## Tone

Tone should be:

- confident but not fake
- technical but readable
- ambitious but grounded
- cinematic but not cringe
- sharp, dense, and proof-backed

## Output format when invoked

When this skill is used, produce one of the following depending on the task:

1. Identity critique
2. Hero copy options
3. Section narrative plan
4. Copy rewrite
5. Full first-five-section messaging system

Always include:

- What is strong
- What is generic/cringe
- What to replace it with
- How the visitor should feel after reading it
