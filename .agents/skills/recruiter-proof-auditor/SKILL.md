# Recruiter Proof Auditor

## Mission
Check whether the portfolio helps Harsh get shortlisted.

The site can be beautiful, but it must also clearly prove role fit.

Target role directions:

- SDE / full-stack
- ML / AI engineering
- data-heavy product engineering
- automation / agentic systems

## First 15 seconds test

Within 15 seconds, a recruiter should know:

1. Name: Harsh Bhardwaj
2. Direction: ML + full-stack + automation
3. Differentiator: public learning trails + GitHub proof map
4. Serious projects exist
5. How to open GitHub/resume/contact

If any of these are unclear, fix the top sections.

## Proof density framework

Every major claim should map to at least one proof artifact.

Examples:

Claim:

> I build ML products.

Proof:

- ML Lab
- FIFA Predictor
- model validation notes
- EDA reports

Claim:

> I build full-stack systems.

Proof:

- NameFrame
- PersonalCloud
- JEDI
- auth/DB/queue/dashboard architecture

Claim:

> I build automation workflows.

Proof:

- ClipHawk
- certificate automation
- Codex workflows
- scraper pipelines

## Red flags

Mark these as major issues:

- too much visual flash before identity
- projects named but not explained
- tech stack listed before problem/system
- no resume/contact access
- no GitHub link in first screen
- weak project proof
- too many tiny projects in main gallery
- generic self-description
- no mobile clarity

## Recruiter-friendly section requirements

### Hero

Must show:

- what Harsh does
- what he wants to be hired for
- GitHub/resume access

### GitHub Map

Must show:

- organized proof, not chaos
- repo clusters
- flagship vs learning separation

### Work Console

Must show:

- capabilities as work lanes
- what outputs Harsh creates

### Project Gallery

Must show:

- serious projects only
- one-line system identities
- proof/tradeoffs

## Scoring rubric

Score each section 1-5:

1 = generic / unclear
2 = looks okay but weak proof
3 = useful but not memorable
4 = strong and credible
5 = exceptional, memorable, proof-backed

Score dimensions:

- clarity
- proof
- role fit
- taste
- mobile readability
- recruiter actionability

## Final standard

A recruiter should not have to guess what Harsh does.
The design should impress, but the proof should convince.
