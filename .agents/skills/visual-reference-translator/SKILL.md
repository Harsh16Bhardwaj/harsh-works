# Visual Reference Translator

## Mission
Use visual references as taste calibration, not as designs to copy.

When Harsh provides inspiration links/screenshots, extract the design principles and turn them into an original portfolio language.

Do not copy layouts pixel-for-pixel.
Do not clone another portfolio.
Do not blindly paste component libraries.

## Portfolio visual identity

Harsh's portfolio should feel like:

- premium dark builder console
- technical field journal
- ML lab archive
- GitHub proof map
- quiet cinematic sakura scene
- serious project case-file wall
- public learning trail

It should not feel like:

- neon hacker cliché
- template SaaS landing page
- anime fan page
- resume cards template
- random 3D portfolio clone
- overly corporate consultancy site

## Extraction framework

For each reference, extract:

```md
## Reference name / URL

### What it feels like
Short emotional description.

### Layout pattern
Hero, grid, sidebar, timeline, cards, sticky sections, etc.

### Typography behavior
Large display text, editorial, mono labels, dense paragraphs, etc.

### Color behavior
Dark/light, accent, gradients, glows, contrast, muted surfaces.

### Motion behavior
Scroll reveals, cursor, parallax, card transitions, ambient animation.

### Interaction behavior
Hover, click, drag, filters, expanded panels.

### What to borrow
Principles only.

### What to avoid
Things that would weaken Harsh's identity.

### Converted rule for Harsh's portfolio
Practical implementation rule.
```

## Design language for first five sections

### Hero

Visual direction:

- dark premium canvas
- soft sakura petals
- glass/console layer
- large confident type
- status chips like system telemetry
- subtle grid/noise layer

Borrow from references:

- cinematic negative space
- high-quality typography
- smooth entrance motion

Avoid:

- too many moving particles
- bright neon clutter
- illegible text over 3D

### About

Visual direction:

- editorial thesis block
- proof-trail microflow
- calm contrast after Hero

Borrow:

- magazine-style statement
- process diagrams

Avoid:

- long personal story
- random profile photo card unless it adds value

### GitHub Map

Visual direction:

- constellation / system graph
- clusters with labels
- repo nodes
- proof density

Borrow:

- network visualizations
- map legends
- filter chips

Avoid:

- overcomplicated force graph that is hard to use

### Work Console

Visual direction:

- three vertical lanes
- console/dash UI
- lane-specific proof

Borrow:

- product dashboard hierarchy
- status panels
- readable cards

Avoid:

- fake terminal spam
- useless metrics

### Project Gallery

Visual direction:

- case files
- serious archive
- bento grid
- architecture thumbnails

Borrow:

- polished card hierarchy
- editorial project summaries

Avoid:

- equal-weight project tiles
- tiny builds mixed with flagship systems

## Design tokens suggestion

Use these as starting direction, not strict final values:

- Background: near-black with subtle blue/purple/brown warmth
- Surface: translucent dark panels
- Primary accent: muted sakura pink or warm rose
- Secondary accent: cyan/blue for technical telemetry
- Text: off-white, muted gray, low-contrast labels
- Border: thin translucent lines
- Glow: rare and soft

## Motion taste rules

Motion should be:

- slow enough to feel premium
- purposeful
- smooth
- readable
- reduced on mobile

Motion should not be:

- bounce-heavy
- everywhere
- scroll-hijacking
- distracting
- dependent on hover only

## Deliverables when invoked

Produce:

1. Reference extraction table
2. Borrow/avoid list
3. Final visual design rules
4. Section-specific implementation guidance
5. Component-level style rules
6. Animation rules

## Strong warning

If a requested effect looks cool but weakens readability, performance, or identity, flag it.
The goal is not maximum animation.
The goal is memorable taste.
